# ARCSS Unity Project --- Documentation

## 1. Project overview

This documentation was generated by statically inspecting the uploaded
Unity project archive. The project appears to be an educational PC
hardware / computer systems learning application with module-based
learning content and interactive assessments.

**Unity Editor version:** `6000.5.1f1`

**Scanned project counts:** - C# scripts under `Assets/`: 80 -
Project-owned scripts under `Assets/Scripts/`: 62 -

`Assets/`: 14 - Prefabs: 35 - `.asset` files: 60 - Shader files: 16

This is a static source/project-file scan. It does not execute the
project in Unity, inspect live runtime behavior, or validate every
Inspector reference.

## 2. Main application areas found

1.  **Main menu and learning content** --- topic selection, module
    lists, text/photo/3D/video content, and profile UI.
2.  **Account and local progress** --- player profiles, avatar
    selection, local JSON save/load, module completion, and assessment
    records.
3.  **Quiz assessment** --- ScriptableObject-driven multiple-choice
    questions, answer validation, results, and score persistence.
4.  **PC assembly assessment** --- selectable PC parts, slots/snap
    points, assembly prerequisites, camera changes, and completion UI.
5.  **PC disassembly assessment** --- dependency-checked disassembly,
    part animation/visibility changes, camera switching, and completion
    UI.
6.  **Networking assessment** --- LAN wire selection/swapping and
    sequence validation for straight-through and crossover cable modes.
7.  **3D model/video viewing** --- model selection, touch rotation/pinch
    zoom, and video playback.

## 5. Main data assets

### Topic and module configuration

`TopicData` is a ScriptableObject with an `ArTopics` value and an
ordered list of `Module` entries. A `Module` can hold: - `content`
(`ModuleContent` enum: text, photo, 3D, or video) - module name and
description - video clip name - photo/text content data reference -
model names and module sprites - assessment flag and
`AssesmentDetails` - initial `isDoneReading` value

`AssesmentDetails` includes quiz-vs-scene assessment configuration,
`QuizId`, assessment scene enum, and `moduleReference` strings used as
prerequisites.

### Quiz configuration

`QuizData` is a ScriptableObject with a `QuizId` and list of `Quiz`
questions. Each question contains answer choices; each choice has a
letter, answer text, and `isCorrectAnswer` flag.

### Assembly configuration

`PCAssesmentData` is a ScriptableObject containing `assemblySteps` and
`disassemblySteps`, each holding a `PCParts` enum value. In the current
`AssembleAssesment` and `DisassemblyAssesment` code, ordered-step
validation is commented out; runtime dependency checks are performed by
`AssemblyPart`.

## 6. Local save format

`GeneralUtility` writes JSON to:

`Application.persistentDataPath/save.json`

The serialized structure declared in `ModuleInitializer.cs` is:

-   `SaveData`
    -   `players: List<PlayerSaveData>`
-   `PlayerSaveData`
    -   `playerId`, `playerName`, `profilePhotoName`
    -   `moduleDatas: List<ModuleData>`
    -   `assesment: List<AssesmentProgressData>`
-   `ModuleData`
    -   `topic`, `moduleName`, `isDoneReading`, `isAssesment`
-   `AssesmentProgressData`
    -   `topic`, `assesmentName`, `isCompleted`, `score`

`AccountManager` stores the last selected profile ID in `PlayerPrefs`
using the key `LocalPlayerSave`. The JSON file stores the profiles and
their progress; PlayerPrefs stores the local selected-profile
identifier.

## 8. Important implementation observations

These are code-level observations, not runtime test results:

-   `GameManager` loads the JSON save in `Awake()` and exposes a
    singleton-style `instance`.
-   `AccountManager.LoadLocalSavePlayer()` attempts to select the
    profile ID stored in PlayerPrefs. If the ID is absent or stale,
    `SetCurrentPlayer(string)` shows a no-account warning.
-   `ModuleInitializer.CheckIfModuleDoneReading()` reads the current
    player's saved module progress. Its current lookup initially matches
    `moduleName`; the save records also contain `topic`.
-   `ModuleInitializer.CompleteModuleReading()` finds existing progress
    by module name, then updates or adds a `ModuleData` record and
    saves.
-   `ModuleContentController.OnFinishedReadModuleContent()` marks
    content complete when `position.y <= 0.01f`; actual callback wiring
    and scroll coordinate behavior should be verified in the scene.
-   `MultipleChoiceManager.OnSubmitAnswers()` records the quiz score
    through `GeneralUtility.SaveAssesmentProgress()` and calls
    `GameManager.Save()`.
-   `AssemblyPart.CanAssemble()` and `CanDisassemble()` enforce
    configured dependency lists. `IsAligned()` exists, but the current
    `TryAssemble()` does not call it.
-   `AssembleAssesment` contains commented-out ordered-step and
    alignment checks. `PCAssesmentData` is assigned but its ordered
    sequence is not currently used by the active `TryAssemble()` flow.
-   `DisassemblyAssesment` similarly has commented-out ordered-step
    checks; it actively checks assembled state and dependency rules.
-   `LanWireInteraction` currently has commented-out drag/drop movement
    logic. The active selection path calls
    `NetworkAssesment.SetLanwire()`, which performs a tweened position
    swap after two wires are selected.
-   `NetworkAssesment.CheckSequence()` derives each cable's sequence by
    sorting wire objects by world X coordinate, then compares both
    arrays against the selected mode's configured correct sequence.
-   `NetworkAssesment.CheckCrossOverAnswer()` is empty in the scanned
    source; final validation is handled by `CheckSequence()`.
